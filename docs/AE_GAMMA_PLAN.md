# 自动曝光与 Gamma 改进方案

初稿日期：2026-10-20；修订日期：2026-10-21。
本文是待验证方案，不代表 RTL 已修改、仿真已通过或已发布新 bit。
本次撤回整组提亮的 Gamma 候选：它同时抬高了亮端，缺少高光与灰阶验证依据。

## 目标与资源基线

优先解决灯光进入画面后背景长期锁暗、明暗切换慢的问题，同时评估亮部细节。
不能只以背景变亮判定改善，也不能预先认定当前 Gamma 需要整体提亮。
保留 1280×720、现有帧率、十三种显示模式、检测与 OSD 功能、像素拍数和帧对应关系。

资源以上一轮正式发布 `src-a4edaf9e0171` 为基线，不能退回压缩前的较大版本比较：

| 最终布局布线指标 | 本轮上限 |
|---|---:|
| Slice | 18,145 |
| LUT6 | 17,665 |
| FF | 17,261 |
| ERAM | 79 |
| DSP | 15 |

Slice 争取继续下降，其他四项也不得超过上限；原时钟约束下 setup、hold 均须通过。
收益以完整工程最终布局布线为准。固定表长度不变，并不保证换表后资源不增。

## 现状与原因

当前 AE 在 LSC、去马赛克、AWB、Gamma 之前统计 RAW10 分量。
每八组四像素采一组，每八行采相邻两行；Bayer 组成是 2R+4G+2B，
不是目标区域或感知亮度测光。RAW10 右移两位后，每个分量截顶到 192。

当前高光计数也以 192 为阈值，即 RAW10 至少为 768，并非只统计 1023 饱和。
高光分量达到 25% 会强制降曝；随后比例保持在 12.5%～25% 时，
即使测光均值低于目标 96～120，也会被锁存逻辑禁止增亮。
现有回归中“20% 亮源、背景分量约 14”的固定场景，均值约 49.6 仍保持曝光，
属于需要修正的控制行为。

当前调参需要 I²C 写入完成，再丢弃三帧、收集六帧。
在 60 fps 下，每步至少消耗约九帧，另加 I²C 时间；多次小步累积造成响应慢。
六帧平均可以抑制部分周期波动，但不能等同于传感器曝光时间已做市电同步。

当前固定 Gamma 是自定义色调曲线：64→80、128→128、192→180、224→210。
它提亮部分暗部，同时压低中高亮。不能仅凭这些锚点就认定亮端需要上调；
应在 AE 固定后用灰阶、真实画面和相同显示设置评估。

## 推荐验证顺序：AE 做对照，Gamma 先保留原表

### 1. AE 只由一个连续、单调的测光量决定方向

以下 **160 截顶是对照候选，尚未确定为生产方案**。
保留现有采样位置、采样密度和完整帧有效性检查，候选截顶由 192 改为 160，
控制器的 `METER_MAX` 同步为 160：

`S = Σ min(RAW10 >> 2, 160)`，`N = 有效采样分量数`。

用 `S` 与常数乘 `N` 比较，不计算除法：

- `S < 96N`：增亮。
- `S > 120N`：减亮。
- 其余：保持，不写相同的曝光/增益配置。

同时删除高光锁存和“高光达到比例就独立反向减亮”的规则。
高光比例不再作为独立的增亮禁令。这样对同一组非负传感器分量，
曝光增加时截顶和不会因为样本被剔除而突然下降。

高光计数接口首版保留，阈值仍为 RAW8 的 **192**，用于诊断与有效性检查。
必须将它和测光截顶参数分开，不能把截顶降到 160 后，悄悄改变“高光率”的定义。
不新增直方图、分区累加器、除法器或跨时钟载荷。

先比较 160 的原因是原来的快慢阈值仍然严格有序：
`64 < 96 < 120 < 144 < 160`，可继续使用既有增益表的快速减亮策略。

这项候选降低了强光对测光的影响，可能以更多亮源饱和换取背景亮度。
例如 25% 分量已截顶、其余背景 RAW8 为 70 时，候选均值为 92.5，会继续增曝；
现版则因高光达到 25% 而减曝。两者的取舍不同，不能称候选同时增强了高光保护。
原高光计数只表示 RAW10≥768，不能据此得出实际饱和率受控。
验收须同时记录背景可见度、原高光率和接近传感器满量程的分量比例；
若候选显著增加重要亮区的剪切，则不采用，不能用显示 Gamma 压暗来掩盖。

### 2. 配套步长与低曝光边界

| 测光区间 | 曝光码步长 | 增益码步长 |
|---|---|---|
| 均值 <64 | 增加当前曝光的 1/2 | 曝光到上限后增加 16 |
| 64≤均值<96 | 增加当前曝光的 1/8 | 曝光到上限后增加 4 |
| 96≤均值≤120 | 保持 | 保持 |
| 120<均值≤144 | 减少当前曝光的 1/8 | 优先减少 4 |
| 均值 >144 | 减少当前曝光的 1/4 | 优先减少 16 |

增亮仍先曝光、后增益；减亮仍先减增益、后减曝光，每次只改其中一项。
曝光与增益上限保留 1991、176，下限保留 4、16。
上述增益步长是 `SC520GainTbl` 的控制码，不是直接的倍率或 dB。

曝光步长按移位取整，最小步长从 **4 改为 1**，曝光下限仍为 4。
这是为避免小曝光时 8→4→8 一类大比例往返，不是把传感器最小曝光改成 1。
所有算术继续使用移位、加减、比较与饱和限幅。

首轮保留三帧生效等待、六帧平均及现有 I²C busy→done 握手。
先用较大的暗场步长减少更新次数，不先缩短等待时间。
只有测得传感器实际生效延迟后，才另行考虑缩短三帧等待。

### 3. 128 截顶作为离线对照候选

128 对小面积亮源的权重更低，可能更利于暗背景，也有缩小统计累加位宽的机会。
但不能只改一个常量后直接发布：

- `METER_MAX` 必须同步为 128，原快速减亮阈值 144 必须调整。
- 候选快速减亮阈值为 127、增益快减步长为 8；曝光快减仍为 1/4，最小步长为 1。
- 不能照搬增益快减 16。当前增益表部分位置减 16 会降到原倍率的约 2/3，
  可能让刚高于目标的画面突然低于目标，再反向增亮。

160 与 128 使用相同场景做对照，只把更合适的一版编入生产，不增加运行时双统计链路。
先验证 160；仅在暗部、过曝、响应和最终资源比较支持时选择 128。

以“20% 分量已经高于截顶”的理想固定场景计算，160 截顶进入目标带所需背景
约为 RAW8 的 80～110；128 截顶约为 88～118。
这只是由测光公式推得的预期，不是已经测得的传感器效果。

全局测光仍有局限：大面积亮屏占据画面时，不能同时保证背景明亮、亮屏细节完整。
例如 75% 分量截顶时，仅亮区在 128/160 两种方案中就分别贡献均值 96/120。
这类场景应记录取舍，不能把全局 AE 宣称为 HDR。

### 4. Gamma 首轮整表保留，撤回整组提亮锚点

先稳定并评估 AE，Gamma 首轮使用现有完整表，不同时抬高曝光目标或显示亮度。
原候选把 192→180 改为 192→201、224→210 改为 224→229，
对已经偏亮的输入继续提亮，削弱了原有亮端抑制，现予撤回。
没有同场景灰阶和高光对照前，不给出另一组任意锚点替代。

后续只有确认显示曲线仍有问题时才生成新候选，并满足：

- 黑位保持 0；低灰调整须检查黑位、噪声和暗部可辨级数，不能默认全部抬高。
- 中间调按实际偏差调整，先以原曲线作基线，不预设 128 必须变成 144。
- 亮端先沿用原表；在当前目标下，新候选的 192～255 输出不得高于原表。
  进一步压低也需有实图依据，不能把“越暗越保护高光”当作验收标准。
- 检查 160～224 过渡和有效输出灰阶，不能只固定亮端、再大幅抬高中间调，
  把两者之间压成很窄的灰阶。单调、无跳变、0/255 端点只是必要条件。

这里的 192～255 是显示 RGB 单通道码值范围，不是传感器过曝判据，
也不能与 RAW8 高光阈值 192 混用。全局单通道查表不识别灯具或具体区域。
传感器已经饱和、或上游已经截断成相同数值的细节，不能由 Gamma 恢复。
应先在 AE 中处理曝光取舍，再用曲线映射仍然存在的层次。

如果后续需要改表，继续离线生成 256×8 常量表，RGB 使用同一映射，各通道独立寻址；
不新增实时幂运算、自动 Gamma 控制环、多套常驻曲线、ERAM 或 DSP。
是否满足资源上限仍须通过完整工程布局布线验证。

作用位置维持在显示效果模块、OSD 叠加之前，仅改变模式 00 的曲线。
Gamma 查表一拍、显示效果总计两拍均保持。
其他十二模式在相同输入下输出不变，模式切换、DE/同步、框与文字的拍数保持。
Gamma 不反馈给 AE，也不插入检测支路。AE 改变传感器曝光后，
检测面对的真实图像会随之变化，因此还需复核实际检测效果。

## 验证与实施顺序

1. 冻结当前正式版本，补充体现问题的新验收用例。现有“20% 高光应保持锁暗”
   的断言应改为“背景仍暗时应继续恢复”，不能把旧行为原样作为正确性标准。
2. 只修改 AE：先验证 160 截顶、统一方向、上述步长和小曝光边界。
   通过后才比较 128 截顶候选，避免同时修改曝光与显示后无法定位原因。
3. 固定 AE 候选，先评估原 Gamma；确有显示曲线问题时才增加新曲线对照。
   使用同一场景、同一曝光/增益记录和相同显示设置评估亮度、灰阶、
   颜色、噪声与过曝。背景变亮但重要高光丢失，不能直接判为改善。
4. 资源初筛后只对合适组合做完整布局布线；全部上限、时序和 CDC 检查通过才发布。
   若换表导致面积增加，应调整曲线或实现再比较，不能用“表一样大”解释超标。
5. 上板核对传感器生效帧、真实灯光波动、移动目标拖影、颜色/形状检测与显示。
   需要市电抗闪时，再根据实际行时长和曝光码单位设计 50/60 Hz 曝光量化；
   不把 10 ms 或约 8.33 ms 直接当作寄存器码写入。

必须覆盖的验证项目：

| 项目 | 验收内容 |
|---|---|
| 固定混合光 | 10%、12.5%、20%、25%、50%、75% 亮源；每组至少 300 帧，同时记录背景可见度、高光率及接近满量程的分量比例，不能只验收背景变亮 |
| 灯光移动 | 同一比例亮源平移、跨采样位置和跨旧阈值；检查长期均值及持续反调 |
| 明暗切换 | 日间→室内夜间、夜间→日间分别记录首次入带、连续 12 帧确认和更新次数；稳定后再观察 30 帧无无谓写入 |
| 步长边界 | 曝光码 4～32、曝光上下限、所有增益分段及快慢阈值两侧；可达目标时不得持续往返 |
| 波动与失效输入 | 噪声、不同相位/频率的照明波动、I²C 生效延迟、缺帧/坏帧、源时钟暂停；无有效统计不得漂移 |
| Gamma | 首轮原表逐项不变；后续候选检查 256 值、亮端不再上抬、过渡区有效灰阶、单调性、0/255 端点、RGB 独立寻址、灰阶中性和原拍数；其他模式与 OSD 回归 |
| 最终工程 | 五项资源不超基线，setup/hold、约束有效性、CDC、帧对应与现有功能回归通过 |

已有生产参数闭环仿真的比较参考为：daylight 40 帧、lit indoor night 105 帧、
daylight recovery 96 帧、10% lamps 114 帧。这些数字包含连续 12 帧确认，
来自小画面、简化无噪声传感器模型，不能直接作为上板实测收敛时间。
后续须在统一新增用例和相同模型下重新比较旧版与候选；
速度是验收项目，不预先承诺节省百分比或固定的一秒收敛。

预期节省来自删除高光窗口累加与锁存控制、按实际范围收窄计数器，
以及选择合适的常量曲线；具体 Slice/LUT/FF 变化必须测量后填写。
