# 单目标颜色与形状检测

日期：2026-10-28。主工程：`td_project/anlogic_edge_osd.al`。

主工程默认采用单目标颜色与形状检测：
`RED_MULTI_ENABLE=0`、`SINGLE_SHAPE_ENABLE=1`。
正常综合主工程即可采用这一路径，不需要另建 TD 工程。

## 本次修改

- 从主工程的综合实例中移除多目标连通域引擎、候选槽、TopN 选择和多目标配对。
- 每帧对选定颜色累计一套轮廓特征，保留一个框、一套形状结果及确认、保持状态。
- DDR 结果桥只传输一组目标，显示端只保留一个框和一条跟随标签。
- 保留红、绿、蓝模式、运动检测、颜色掩码、去噪、膨胀、腐蚀及闭运算。
- 保留原形状分类器的面积、周长、一阶矩、重心和四方向投影判据；未替换成单纯填充率算法。
- 保留相机、ISP、AE/AWB、DDR、HDMI、水果 CNN、图像特效、延迟显示及 Logo。

旧多目标实现仍在源码中供对照，但默认主工程不实例化。
最终综合网表中没有 `gen_multi` 引擎路径；颜色前端的三块掩码行存储器仍存在。
从 `module red_multi_run_engine` 开始到文件结束的原引擎和形状分类器，
与本轮修改前的冻结基线逐字一致。

## 单目标的含义

该版本累计选定颜色在整帧中的外接框，不挑选“最大连通域”。
同一画面中有多个分离的同色物体时，它们会合成一个外接框；
检测到分裂行或不连通轮廓后，形状输出未知，颜色框仍可使用。

目标连续匹配两帧后显示。短暂丢失时最多保持两帧，第三次丢失清空。
形状标签变更也需要连续确认，切换检测模式时清空旧状态。
清空后必须看到新起帧，避免尚在掩码流水线中的旧尾拍重新发布结果。

## 综合结果

使用同一份冻结基线、同一 TD 工具和约束，只运行综合。

| 资源 | 修改前 | 单目标最终版 `single_final` | 减少 |
| --- | ---: | ---: | ---: |
| Slice 综合估算 `#slice*` | 23,247 | 21,583 | 1,664 |
| LUT | 30,322 | 27,648 | 2,674 |
| 寄存器 | 19,759 | 18,802 | 957 |
| ERAM | 100 | 92 | 8 |
| DSP | 40 | 40 | 0 |

器件容量为 21,216 Slice、108 ERAM、40 DSP。
单目标最终版的 Slice 综合估算仍超过容量 367，约为容量的 101.73%。
TD 报告明确说明 `#slice*` 不是布局后的最终占用，因此不能据此宣称已经能放下，
也不能宣称布局布线必然成功。

最终综合时序：SWNS **+0.288 ns**，STNS **0 ns**；
HWNS **+0.114 ns**，HTNS **0 ns**，STA coverage **94.31%**。
这是既有约束下的综合时序结果，不代表布局布线后的时序。

单目标版本的两次对比综合曾在原有运动平滑链出现小幅建立时序违例。
最终版保留运动算法，利用原始运动框按八像素块对齐这一既有条件，
在平滑运算前固定最大坐标的低三位，切断 found 信号进入整条算术链的路径。
该替换值只在有效候选分支使用；该分支的原坐标低三位本来就是全一。
历史平滑坐标仍保留完整精度，确认、关联、保持、释放和发布周期不变。
通用 `motion_result_stabilizer` 的参数默认关闭这项专用处理，
只有直接连接原始块运动检测器的生产实例将其开启。
