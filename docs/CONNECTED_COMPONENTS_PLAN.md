# 低资源多目标连通区域方案

更新日期：2026-10-17。状态：方案，尚未实现 CCL、多个检测框或逐目标跟踪 RTL。
九种显示算法的构建不包含本方案，不能把显示效果、单个合并框或本方案当作已完成的多目标识别。

## 目标与首版范围

在 720p 图像旁路形成 160×90 的二值前景图，按八连通分开统计区域，
输出面积最大的最多 4 个有效区域及各自的外接框。
先接现有帧差运动前景，验证“两处独立运动分别出框”；再接红色候选。
像素主路不反压，不增加 DDR 图像读写，不保存整幅标签图，不另开时钟。
新增状态机和片上 RAM 在已有 CSI 时钟域运行。

这里的八连通指水平、竖直和对角相邻的前景单元均属同一区域。
物体一旦在二值图中连在一起，CCL 就会将其视为一个区域；
相邻帧差可能同时包含物体新旧位置，CCL 本身不能恢复真实物体轮廓或身份。
8×8 分块也可能将距离很近的两物体合在一起。它是候选区域提取，不能单独识别台阶或判断可通行性。

## 先接现有哪一段

| 现有模块 | 已有能力 | 新增接口或注意点 |
|---|---|---|
| `motion_target_detect_96.v` | 8×8 灰度均值帧差、邻域支持和全局明暗变化判定 | 导出真正受支持的中心前景位、块坐标、帧首/结束和帧有效性 |
| `red_target_detect_96.v` | 四像素并行红色判定、3×3 多数过滤 | 从多数滤波后的四位掩码统计每个 8×8 单元的命中数 |
| `target_detect_switch_96.v` | K2 逐帧选择红色/运动，运动单框稳定器 | 锁存该帧 CCL 掩码类型；多个区域不能直接套用一个单轨迹稳定器 |
| `design_top_wrapper.v` | 当前单框邮箱和四个 DDR 槽结果表 | 扩为 Top4 结果，并加入原始帧身份和槽代次 |
| `video_latency_monitor.v` | 已有 10 位帧号、实际写槽/读槽及时间绑定 | 复用帧身份产生和配对原则，不假定现有目标邮箱已经携带这些信息 |
| `hdmi_mixer.v` | 单框叠加、显示帧首锁存 | 最多四组框比较；显示帧内冻结整组结果 |

运动生产参数仍为均值差门槛 10、最少 12 个变化块和 40% 全局变化门槛。
应接 `filter_supported` 语义的“中心原本命中且邻域支持”掩码，
而不是把已有总框重新栅格化，也不是把邻域所有投票点扩张后全部当作真实前景。
现有窗口处理中心坐标是 `(line_x-1,line_y-1)`；
首版明确将最外一圈块填 0，内圈中心逐个写入，不能声称已经覆盖未排空的右/下边界。
全局明暗变化、坏参考或短帧一律令整帧 CCL 无效。

红色入口用已有多数过滤后的红色像素，首版每块命中数达到可配阈值才记为 1，
例如 4/64 只是待样本验证的起点。它仍是红色检测，不包含绿色灯；
模式 05 的红绿保色不是检测掩码来源。小灯可能被分块和门槛漏掉，
信号灯候选需要独立检验最小尺寸，必要时另设局部高分辨率 ROI。
两类前景分开处理，不将红色与运动掩码做 OR 后混成一类。
K2 在帧首确定本帧写哪类掩码，两种原检测仍持续运行，运动参考不随 K2 清空。

## 缓存与任务生命周期

两个掩码银行各为 160×90×1 = 14,400 bit，总计 28,800 bit，约 3.52 KiB。
建议每银行按 900×16 bit 打包，不用 28,800 个触发器逐位保存。
生产端保持一个 16 位组装寄存器；非输出边界的 0 和内部前景位都按明确坐标写入，
完整帧封存前必须验证 14,400 个逻辑位置均已定义，不能沿用上帧残留位。

每个银行使用 `FREE → CAPTURING → READY → PROCESSING → FREE` 状态。
CSI 帧首只获取 `FREE` 银行；若无空闲银行，整帧跳过，累计 `capture_drop`，
不覆盖 `PROCESSING` 银行、不暂停摄像头。`READY` 银行至多一个待处理，
需要丢弃旧待处理任务时显式使其标签和结果无效。
结束标记、短帧、复位、场景变化和超时都必须有银行释放路径。
标记无效后，只能在下一次完整覆盖或清零完成后再次封存。

## 真正的连通区域处理

首版采用行程段 RLE 与串行并查集，不为 14,400 个位置保存标签。
一行中连续的 1 组成一段 `{x_start,x_end,label}`。
160 位交替的最坏输入每行最多 80 段，90 行最多 7,200 段；
这只是行段数上界，不表示只需 7,200 个时钟就能完成。

两个行段表各 80×24 bit：起点 8 位、终点 8 位、临时标签 8 位。
标签 0 表示背景，前景临时标签使用 1..255，整帧不回收、不重用。
标签上限针对临时标签，不只是最后区域数；一张最终只有少数区域的图也可能在早期耗尽临时标签。
第 256 次申请立即触发 `label_overflow`，整帧结果无效，不发布已经积累的部分框。
首版不实现复杂的标签回收，以免把有限容量的方案写成无限区域能力。

相邻两行的段在满足以下条件时八连通：

```text
current.start <= previous.end + 1
previous.start <= current.end + 1
```

比较先扩为 9 位，避免边界加 1 回绕。每行段按起点排序：
保存前一行游标，跳过 `previous.end+1 < current.start` 的段，
再扫描所有满足 `previous.start <= current.end+1` 的重叠段。
长的前行段可与多个当前段相交，因此不能遇到一次重叠就永久跳过它。
具体游标推进与回访要用软件整数参考逐例验证；不采用每个当前段遍历全部 80 段的暴力比较。

没有重叠则分配新标签；只有一个根则使用它；多个不同根则依次合并。
并查集只合并根，使用按秩合并，秩相同时以较小标签作确定性决策。
255 个前景标签的秩范围为 0..7，父指针 8 位、秩 3 位，另加有效位。
根查找最多跨 7 条父边；首版不做路径压缩，避免额外写端口和读写冲突。
行段中保存临时标签，后续使用前重新查根，不能将旧的非根标签直接当作最终区域。
每次 union 完成后才开始下一次查找，不使用未经提交的父指针值。

每个临时标签另存 `{xmin,xmax,ymin,ymax,area,valid}`，
使用 8 位坐标×4、14 位面积和有效位，按 48 bit 打包。
当前段只给选定标签增加一次面积 `end-start+1`，并更新四个边界；
合并父指针时不同时搬运统计，防止多次合并重复计数。

扫描结束后停止 union，依次处理有效标签：

1. 查出最终根；若标签本身为根，保留已有统计，不给自己重复相加。
2. 若为非根，将该标签的原始统计加到最终根，更新根边界，再清除该非根统计。
3. 所有非根仅处理一次，且只向最终根写入；根在这一阶段不会再变。
4. 最后扫描根统计，做面积/尺寸过滤并选出 Top4。

因此只需一张统计表，无须额外复制整张根统计表。
面积、坐标及父表必须在任务初始化时清零或以本任务有效位隔离；
新标签分配前显式写入 `parent=self,rank=0,area=0` 和边界初值，
不依赖 ERAM 上电内容。

## RAM 端口与周期预算

每个 RAM 都按厂商实际配置的注册读延迟调度；初版预算按一次读需 2 拍返回，
每次写 1 拍，不把同步 RAM 当组合数组。
处理器每次只提交一个查根、union 或统计读改写操作：
`发读地址 → 等待数据 → 判断/运算 → 必要时写回`。
同一表不在同拍发起不受支持的多个地址读写，也不依赖读写同址的未定义返回值。
掩码银行的捕获写与另一个银行的处理读独立；单银行不同时捕获和处理。

状态机阶段为：初始化、逐字读掩码/建行段、前行重叠查找、
查根/合并、段统计、最终统计归并、Top4 选择、发布或丢弃。
工作周期计数覆盖全部阶段及等待拍，不能只统计 14,400 次位扫描。
若全段两两比较，最坏已有 7,200×80 = 576,000 次重叠判断，尚未包含查根和 RAM 等待；
这也是需要有序游标和完整周期测试的原因。

已有 CSI 时钟约 103 MHz，60 帧/秒对应约 172 万时钟/帧，作为预算尺度。
首版可先设不超过 1,000,000 个 CSI 周期的任务看门狗（约 9.7 ms），
包含清表、统计和发布准备；这是拟定工作量上限，不是已达到的处理延迟或实时性证明。
真正的有效截止时刻还受该原帧最早开始 HDMI 显示、DDR 槽复用和邮箱传输时间限制。
实施前必须测量实际原帧 EOF 到 HDMI 读槽冻结的可用间隔，并为结果传输留出余量。
若该间隔短于最坏处理及交接时间，应先提高处理吞吐或调整图像/结果调度，
再明确可保证的检测更新频率；不能只靠丢弃迟到结果，导致持续无框却宣称满足显示需求。
超出看门狗、原帧已过期或槽已复用，均丢弃整组结果并计数；不能半途输出不完整 Top4。
实施后测量典型、95% 分位及最大周期和任务丢弃率，再决定更新频率或调整容量。

## 输出与面积含义

每个根满足参数化最小面积、最小尺寸和长宽范围后，按面积降序选最多 4 个；
同面积按根标签排序以保证参考可复现。
可先从最小 8 个支持块试验，但它不是现有单总框的 12 变化块门槛的等价替换，
也不是未经实拍验证就可确定的最终运动参数。

输出每个区域的块坐标、`area_cells` 和类别。720p 外接框换算为
`xmin=8*cell_xmin`、`xmax=min(1279,8*cell_xmax+7)`，y 同理并限幅到 719。
`area_cells` 是前景块数量；`area_cells*64` 是等效覆盖像素，不能写成物体精确面积。
红色若只保留 1 bit 块掩码，同样不能恢复已有全分辨率红色像素计数。
今后需要精确颜色面积时，要另存块命中数并将其计入位宽、统计和资源预算。

超过 4 个合格区域时，Top4 仍可作为明确受限的有效输出，同时置 `more_components`。
它与标签溢出、短帧、全局变化和超时导致的整帧无效不同；这些状态必须分别统计。
首版输出区域编号只表示本帧排名，不宣称为跨帧稳定物体 ID。
后续跟踪需要最多 4 条独立轨迹、匹配和各自确认/保持状态；
现有单框稳定器不能原封不动地同时管理多个目标。

## 原帧与 DDR 槽必须绑定

现有目标邮箱是 89 位、四槽记录每槽 86 位，包含显示配置、检测模式和一个框，
没有多框、面积或可用于延迟任务的完整原帧身份。
当前即时检测完成时使用同步的当前写槽；将 CCL 延迟结果简单接到同一处会把旧结果归给新帧。
已有 32 拍等待主要用于槽无效化，不是离线统计的可用时间预算。

掩码开始捕获时记录原始 `frame_id` 与时间/递增任务号；
通过该帧真实的 DDR 写分配事件匹配 `{slot,slot_generation}`，
不是在 CCL 完成时读取“当前写槽”。10 位帧号会回绕，
不能仅凭相同低 10 位就认定为同帧；需和槽代次、时间或足够宽的单调序号联合验证，
并规定任务最大寿命，令寿命小于相关计数回绕时间。
帧被输入错误中止、未完整写入、槽回滚或复用，均使对应任务无效。

每个封存任务保存 `{frame_id,slot,slot_generation,effect_config,detect_mode,frame_valid}`。
发布时再次核对该槽仍保存相同原帧，且图像已完整写入；
结果整组经过握手邮箱传至 HDMI，发送端在 ACK 前保持 payload，不覆盖忙邮箱。
接收侧也核对代次，更新匹配槽的 Top4 记录。
本方案预计 payload 为数百位，需重新核对 CDC 约束覆盖和邮箱吞吐，
不能直接沿用现有 89 位宽度及路径数量。

HDMI 在实际读槽选择时冻结该帧候选记录，在首个显示像素提交，整帧保持。
结果没赶上该帧冻结点时，该次显示不画 CCL 框；若随后重复显示同一原帧，
可在下一次帧首使用仍匹配的结果。绝不将前一摄像头帧的框直接标成当前帧结果，
也不在屏幕扫描中途换框。坐标补偿仍按该帧显示模式：
Scharr/漫画/Scharr 反色各 `(3,3)`，浮雕/形态学各 `(1,1)`。

## 存储与逻辑预算

下表为本方案逻辑位宽，不是综合报告：

| 内容 | 配置 | 原始 bit |
|---|---|---:|
| 双掩码银行 | 2×900×16 | 28,800 |
| 双行段表 | 2×80×24 | 3,840 |
| 父指针、秩、有效位 | 256×12 | 3,072 |
| 标签统计 | 256×48 | 12,288 |
| 合计 | 不含帧结果邮箱、寄存器和 RAM 端口取整 | 48,000 |

原始总量约 5.86 KiB，但不能按 48,000/20,480 直接认定为 3 个 ERAM。
双银行必须独立；48 位统计、24 位行段和 12 位父表还需按实际 RAM 模式取整。
在 16/24/48 位可由合适基本宽度拼接、每表注册读的假设下，
双掩码先留 2 个 ERAM，双行段 1～2 个、父表 1 个、统计表 2～3 个，
初步按 6～8 个 ERAM 设计、预留 10 个 ERAM；这不是已证实的物理上限，
最终由安路 IP 配置和独立综合确认。
若工具只能使用较窄端口，所需物理块可能增加，不能为了守估算而把表映射成大量触发器。

串行 CCL 状态机、Top4、元数据和最多四框显示初步预留约 800～1,500 LUT6、
900～2,100 寄存器、0 DSP；尚未独立综合，不据此推算确定的 Slice 增量。
逐目标跟踪、精确红色面积、小图裁剪、特征和 SVM 均未包含。

已发布九模式 `src-0917069cbe5c` 的基线为 Slice 16,035/21,216、
LUT6 14,773/21,216、寄存器 13,573/42,432、ERAM 69/108、DSP 13/40。
因此剩余 Slice 5,181、LUT6 6,443、寄存器 28,859、ERAM 39、DSP 27，
这些容量不能相加。若新模块实际使用 10 个 ERAM，整机将为 79/108，
还须为后续识别保留资源；上述计算只展示存储预留，不证明整机时序或布局可行。
当前 bit 未包含任何 CCL 实现。

## 验证与实施顺序

1. 先用整数参考生成同一 160×90 掩码，以八连通逐区域比较面积和四边界。
   拟用 OpenCV 的 `connectedComponentsWithStats` 作为独立软件验收工具，
   实施时先固定版本、八连通参数和输入类型；本轮未执行该工具；
   比较统计集合，不要求两种算法的标签编号相同。
2. 验证 RLE/并查集独立模块：空图、满图、孤点、对角接触、孔洞、U 形桥接、
   两根多次合并、长段跨多个短段、宽度 159/160 边界、首末行、同面积排序，
   以及 255/256 次标签申请、超过 4 个区域和所有无效退出。
3. 核对每个前景位只计数一次，并用厂商同步 RAM 模型检查注册读延迟和同址冲突。
   测量全部 FSM 周期，构造高段密度、深树和频繁合并的上界场景，
   超预算必须整帧丢弃；不以通常场景通过代替最坏调度。
4. 集成运动掩码，验证多个独立运动、静止、曝光突变、短帧、参考暖机、
   首末块边界、K2 切换及无空闲银行；检测旁路不能改变视频像素与字数。
5. 集成帧身份和 Top4 邮箱，覆盖四槽复用、帧号/代次回绕、迟到、乱序候选、
   发送繁忙、HDMI 重复旧帧、读槽冻结和复位，确认所有框对应同一原帧。
6. 通过独立综合后再接四框显示并运行全工程布局布线。
   实拍记录多目标分离率、漏检/误报、区域大小和最大延迟；
   运动分支稳定后再评估红色候选与信号灯最小尺寸。
