# 水果识别区域改为左侧居中的横向长方形

状态：历史方案。现已按用户要求恢复原 480×480 正方形，并将实际取图和显示框一起平移至左侧画面中央；当前实现见 [正方形回退报告](FRUIT_ROI_SQUARE_CENTER_20261031.md)。本文以下坐标、补边行为和资源讨论只对应先前长方形版本。

日期：2026-10-31。主工程仍为 `td_project/anlogic_edge_osd.al`，生产图像为 1280×720，右侧水果栏占 320 像素。仅修改识别区域及其验证，不运行综合、布局布线、bit 生成、板卡下载或 Flash 操作。

## 区域与数据链

识别区域为 640×480，位于水果栏左侧 960×720 画面的中央：

| 项目 | 坐标或范围 |
|---|---|
| 中心 | (480,360) |
| 左上角 | (160,120) |
| 采样区域 | x∈[160,800)，y∈[120,600) |
| 显示右下角，含末端像素 | (799,599) |
| 边框 | 沿用 2 像素及水果类别色 |
| 左右空白 | 各 160 像素，右侧以 x=960 的侧栏起点计 |
| 上下空白 | 各 120 像素 |

`fruit_merged/fruitfixed_system.v` 的 `ROI_X/Y/WIDTH/HEIGHT` 参数统一控制实际取图和四处框发布：复位后初始引导框、平坦或背景画面完成、CNN 分类完成、停止事件。框与类别、源帧号沿用原 CDC 邮箱，在 HDMI 帧边界一起锁存。右下角按显示器闭区间约定减 1，修正旧配置的框比实际取图多 1 像素的问题。

`hdmi_mixer.v` 的生产动态框逻辑无需改动。左下检测与算法、右下独立延迟、水果双语侧栏、kg 和价格的布局保持。原安路计数器在 y=120 附近的叠加优先级保持。

## 保持水果形状的输入处理

`fruit_merged/handfixed_preprocess.v` 新增常量参数 `CLASSIFIER_ROI_WIDTH/HEIGHT`。当前生产参数为 640×480，等比例缩小至 128×96，上下各填充 16 行训练使用的 RGB `(124,116,104)`，形成原来的 128×128 CNN 输入。不会将长方形直接横向压成正方形。

有效内容的源坐标为 `x=162+5×ox`、`y=122+5×(oy−16)`，其中 `ox=0..127`、`oy=16..111`。最后有效源样本为 `(797,597)`，完整双线性采样和裁剪边界仍由 ROI 宽、高限制。两维使用同一缩放步长，填充行不推进源 y。

输出仍为 128×128、三通道 CHW、每个归一化值 16 位，保持 6144 个 DDR 写拍、原三平面地址、归一化表、24 路 CNN 计算和网络描述不变。绿色流继续输出全部 16384 个位置，包含填充行，背景参考仍能完成 1024 个抽样点。

背景参考的 1024 个抽样中，固定填充占 256 点，实际内容占 768 点。保留原进入/退出阈值 64/32，相对实际内容的变化比例阈值为约 8.33%/4.17%，比旧正方形的 6.25%/3.125% 更保守；本轮没有额外修改背景检测门限，上板时需一并确认放入、取走水果的响应。

参数默认均为 0 时，预处理保留原 `roi_side` 正方形接口。历史手势源和生成工程未改。当前主工程的水果 ROI 由系统参数控制，冻结模型配置文件中的旧正方形坐标不再驱动生产裁剪；模型地址、长度、CRC 和权重二进制保持，因此已有正确模型无需重新写 Flash。
