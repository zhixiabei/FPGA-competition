## 操作与画面

- 上电为 `00 COLOR GAMMA` 和红色检测。**K1（D5）**继续单向循环九种显示模式，
  **K2（A9）**切换红色/运动检测；K3（B9）、K4（C7）无操作。
- K1/K2 按下和释放均消抖 20 ms，长按只触发一次。模式在摄像头帧首生效，
  显示配置及检测结果随实际 DDR 帧槽传到 HDMI。
- 红色检测最多显示四个框，轨迹槽 1/2/3/4 分别为红、青、黄、绿。
  完整跟随标签为 `1 RED OK`，漏检保持时为 `1 RED H`，其余槽替换编号。
  空间不足时退化为 `1 OK` / `1 H`；找不到安全位置时省略该标签，仍保留框。
- 标签尝试放在框附近，避开已有固定 OSD、延迟面板及其他跟随标签。
  左下角显示 `RED COUNT:0..4`；容量溢出时显示 `OVF`，该帧不画框。
  运动模式显示 `MOV COUNT:0..1` 和一个运动总框，标签为 `1 MOV OK`。

编号表示固定轨迹槽，不是当前帧面积排名，也不是物体类别。
先用彼此分离、尺寸足够的两到四个红色物体验证；稳定出现两帧后才显示新红框。
短暂漏检时保持原框两帧，第三个漏检帧清除。
K2 切换清除红色队列和轨迹，切回红色后重新确认，避免旧结果复活。
检测仍读取 AWB 后、显示效果前的 RGB，因此九种显示模式均可叠加相同的红色检测。

## 实际算法

```text
AWB 四像素 RGB
  -> 原红色通道判定
  -> 原 3×3 多数滤波
  -> 行程段与带帧号 FIFO
  -> 16 项候选连接/退休
  -> 合格区域中支持像素最多的四个
  -> 四轨迹匹配、确认和保持
  -> 原帧/DDR 槽绑定
  -> 四框和跟随标签
```

1. 复用 `red_target_detect_96.v` 的全分辨率红色掩码和 3×3 多数滤波，
   不是先缩为 160×90 块图。生产颜色门槛为 `RED_MIN=24`、`RED_DELTA=6`，
   并保留通道比例与红色色相筛选。最外侧像素遵循原窗口边界处理。
2. 将连续有命中的四像素拍合成行程段，记录首末命中坐标、行号及实际过滤命中数。
   同一四像素拍内有间隙的命中按一个段近似处理，因此不保证分开四像素拍内部的邻近小目标。
3. 深度 64 的 FIFO 保存 `RUN/END/OVERFLOW/ABORT` 描述符及 10 位原帧号，
   为结束和错误标记保留空间；后续帧首不会把正在排队的上一帧结果改成新帧。
4. 串行扫描最多 16 个活动候选，按同一行/相邻行区间相交及相邻一像素连接。
   每项只保留当前行和前一行的一个合并区间；已不可能继续连接的候选退休。
   退休时要求过滤命中数至少 128、宽和高至少 8 像素，保留支持像素最多的四个合格候选。
5. 四个轨迹槽按最近邻距离逐对做一对一关联。新目标第一帧只建轨迹，
   下一帧匹配后确认；已确认轨迹允许漏检两帧。坐标直接跟随匹配候选，
   不采用运动分支的四分之一平滑策略。

候选表和 FIFO 使用安路同步 ERAM 封装；候选读取与判断分级，
避免把 RAM 输出、行判断、区间相交和边界写入串在同一拍。
没有新增 DDR 图像读写、整帧标签图或独立算法时钟。

## 容量与识别边界

本版是有限容量的扫描线区域连接，**不是完整 CCL**。
单候选每行只有一个合并区间，不能记录同一连通区域在该行的多段空隙。
例如 U 形、环形或分叉区域的两个臂可能形成一个宽区间，
间隙内的独立红目标可能被一起合并。需要严格区分这类区域时，
应实施保存全部行段和等价标签的完整 CCL；原方案见
[连通区域设计规划](CONNECTED_COMPONENTS_PLAN.md)。

16 项限制是同时活动候选数，不是全帧物体总数。FIFO 满或活动候选耗尽时，
整帧结果无效，清除该帧框和轨迹并报告 `OVF`；
不会把未完成的局部结果或原单总框冒充四目标结果。
超过四个合格区域但未触及容量限制时，只输出四个最大候选。
复杂噪声、密集行段可触发溢出，不能将四个简单矩形的吞吐测试视为任意图案的最坏吞吐保证。

最近邻轨迹不包含外观特征、速度预测或遮挡恢复。
两个目标交叉、合并再分开，或单帧位移很大时，可能换号、重新确认或漏框。
红色判定也不等于红绿灯识别；红墙、衣服等均可能成为候选。
本版没有将运动前景改为多个目标，也没有 CNN、台阶或障碍物识别。

## 帧身份、DDR 与跨时钟

`target_detect_switch_96.v` 为红色与运动结果保留各自的原帧号和帧首检测模式。
红色可在下一次 SOF 后才完成；结果选择按其携带的帧号查上下文，
而不是读取当前帧模式。两种完成脉冲同时出现时，先发布红色、暂存运动结果；
接口约定每个检测器每帧最多发布一个结果，不支持任意密集的连续双源完成流。

`target_frame_bridge.v` 在帧首记录 10 位 `frame_id`、16 位递增 `nonce`、
显示配置和检测模式。在真实 DDR 写槽分配时绑定这些身份，
结果只有帧号、nonce 和模式都匹配才可写入对应槽。
四个上下文槽使用完整帧号校验，过期、已被替换的上下文被丢弃；
不能仅凭帧号低两位或回绕后的同一帧号接受旧结果。
完整 720p 帧要求 172,800 个 128 位写字，短帧不能使结果成为可显示有效记录。

DDR 实际选择读槽时冻结结果快照，HDMI 在帧首提交整组框、保持标记及显示配置，
同一显示帧内不改框。冻结点后才到达的结果不补画到当前扫描帧；
下次再次读取仍匹配的完整原帧时才可使用。
槽复用、写入回滚、重复显示、早到/迟到结果均有专门回归。
显示偏移随原帧配置绑定：模式 02/06/07 向右下各 3 像素，
模式 04/08 各 1 像素，其他为 0，补偿后限幅到 1279×719。

元数据采用保持载荷的请求/确认传输，发送方在 ACK 前不覆盖正在传输的总线。
两份顶层 SDC 都约束帧上下文 CSI→DDR 为 **20 ns**、
检测结果 CSI→DDR 为 **20 ns**、读槽快照 DDR→HDMI 为 **13 ns**；
异步请求/确认只在第一级同步器入口排除异步时序。
显示配置系统时钟→CSI 邮箱另保留 **13 ns** 约束。
最终构建已核对三组目标元数据约束全部有效：
上下文 7,872 条、结果 4,132 条、显示快照 247 条；显示配置为 4 条。
