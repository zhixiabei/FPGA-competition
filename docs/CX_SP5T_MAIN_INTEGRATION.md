# 总工程 CX-SP5T 自动播报

统一工程包含 HX711 称重、五类水果计价及 CX-SP5T 自动播报。当前入口与模型依赖见 [首页](../README.md)。

## 播报行为

SW2 ON、称重已标定、价格有效时，重量和总价在稳定窗口内变化不超过 2 g / 1 分，持续至少 1 秒且收到至少 3 组新数据，自动播报。超过 2 秒没有新有效数据就取消候选，不能用持续为高的 valid 信号重复计数。

例：227 g、182 分 → “零点二二七千克、一点八二元”。重量保留 3 位小数，金额保留 2 位小数。整数逐位读，例如 12.50 元读“一二点五零元”，无需“十、百”录音。

同一结果只播一次。取走物品、空秤小于 20 g 并稳定后，允许下一个相同重量的物品再次播报；空秤本身不播报。重量为精确零且没有水果识别结果时，也通过真实的新称重更新脉冲完成此复位。

SW2 OFF、未标定、传感器故障、超量程或没有有效计价时，不启动新播报。已发出的组合播放由语音模块继续完成。模块忙时等待，不连续打断当前播报；通过返回串口查询实际播放状态，最长等待 30 秒后恢复，故需接回 TXD。

默认串口 **9600、8N1**，音量 **30（0～30）**。上电等待约 1 秒，再选择 TF 卡、发送音量命令。音量命令为 `FE 08 FF FF 13 1E 35 BE`。

## 接线

先断电接线，语音和 HX711 必须与 FPGA 共地。

| 模块接口 | 开发板排针 | FPGA 球位 / 工程信号 |
|---|---|---|
| CX-SP5T RXD | J2 第 22 脚 | N2 / `I_button[0]`，FPGA 发送 |
| CX-SP5T TXD | J1 第 15 脚 | J14 / `I_button[1]`，FPGA 接收 |
| CX-SP5T 5V | J2 第 11 脚 | 5V 电源 |
| CX-SP5T GND | J2 第 12 或 30 脚 | GND |
| HX711 DOUT / DT | J2 第 1 脚 | V2 / `I_hx711_dout` |
| HX711 SCK / CLK | J2 第 2 脚 | V1 / `O_hx711_sck` |
| 支持 3.3V 的 HX711 VCC | J2 第 29 脚 | 3.3V 电源 |
| HX711 GND | J2 第 30 脚 | GND |

`J14` 是 FPGA 封装球位，**不是 J1 第 14 脚**。以板上 J1/J2 排针序号及球位核对，资料中 GPIOA/GPIOB 的别名有不一致之处。语音供电为 5V，FPGA IO 为 3.3V；接入 FPGA 的返回串口应为 3.3V 电平。扬声器接语音模块的扬声器端子。

播报时拔掉**语音模块自己的 USB/Type-C 数据线**，退出文件下载模式；FPGA 开发板的 USB 线可保留。

## 音频文件

TF 卡使用 FAT32、容量不超过 32GB，根目录建立大写 `ZH` 文件夹。使用两位编号文件名：

| 文件 | 内容 |
|---|---|
| `/ZH/01.mp3` ～ `/ZH/10.mp3` | 零、一、二、三、四、五、六、七、八、九 |
| `/ZH/11.mp3` | 千克 |
| `/ZH/12.mp3` | 元 |
| `/ZH/13.mp3` | 点 |

可使用模块支持的 WAV，编号保持一致，避免同编号重复文件。录音首尾少留静音，使组合播报连贯。

## 上板测试

1. 从工程根目录打开 `td_project/anlogic_edge_osd.al`，主程序 bit 位于 `td_project/anlogic_edge_osd_Runs/best_result/`。
2. 按上表接线、准备 TF 卡，拔掉语音模块数据线，上电。确认 U30 权重与当前模型配置匹配，详见 [Flash 模型说明](FRUIT_FLASH_BOOT.md)。
3. SW2 ON。空秤约 2 秒自动去皮，也可以按 K2（A9）去皮。放上 **227 g** 参考物，按 K3（B9）标定；标定参数掉电不保存。
4. 放上可识别水果，确认 HDMI 重量和金额有效，等待稳定后播报。相同读数继续放置应不重复播报。
5. 取走并等待空秤稳定，再放回相同物品，应再次播报。SW2 OFF 时不应启动新播报。

五类单价沿用总工程：苹果 8、香蕉 6、葡萄 12、橘子 5、草莓 20 元/kg。金额仍由原计价模块四舍五入到分，超出 99.99 元或无有效识别时不播报。

## 源码与验证

`design_top_wrapper.v` 在现有 `handcnn_recognition` 分支中连接 `checkout_scale_core` 的数值输出、有效标志和状态到 `checkout_voice_bridge`，使用同一个 66.666667 MHz DDR 用户时钟。原有 HDMI BCD 跨时钟通路不变。

`fruit_checkout.weight_updated` 每次产出新重量时输出一个时钟周期脉冲，包括精确零；`checkout_scale_core` 以真实重量有效性过滤该脉冲。语音只在空秤复位时使用它，非空物品使用计价 valid 上升沿取得完整的重量/金额组合。状态 10 为正常重新计算间隙，保留去重记录，不能将每次重新计算当作重新启用。

`user_source/hdl_source/voice/` 包含接口适配、稳定判定、十进制音频组合、自动播报控制及 CX-SP5T 串口封包。顶层显式设置 `.VOLUME(30)`。引脚约束沿用 N2/J14；SDC 只对新 UART RX 和 SW2 的第一级同步寄存器添加异步输入例外。

执行回归（需要 ModelSim）：

```powershell
python -B verification/run_scale_voice_tests.py --modelsim C:/altera/14.1/modelsim_ase/win32aloem
python -B verification/check_merge_readiness.py
python -B verification/test_voice_project_sources.py
```

回归覆盖五类价格、105 组十进制组合、串口原始波形/校验、音量 30、返回状态、播放超时、稳定/漂移/去重，并用实际计价 RTL 和生产用语音适配模块验证 SW2、故障、重新计算间隙、精确零空秤复位及陈旧 valid 信号。
