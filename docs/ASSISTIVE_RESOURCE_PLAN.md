# 出行辅助系统：传统视觉与线性 SVM 资源规划

更新日期：2026-10-17。状态：出行辅助识别方案仍在规划；尚未训练 SVM 或实现新增识别 RTL。图像展示已改为统一算法选择，范围见下节，最终资源以对应构建报告为准。

## 结论

按用户决定，去掉小神经网络方案，后续按“传统图像处理 + 线性 SVM + 时序跟踪”规划信号灯识别。盲道、斑马线优先采用颜色、纹理和几何分析；超声波、外置语音和振动保留。

信号灯分类器只处理裁剪出的候选区域，不承担完整 720p 场景的通用目标检测，不识别倒计时数字，也不能单独判定哪个信号灯对应使用者的过街方向。线性 SVM 仍需用实拍样本在电脑上训练，其准确率、资源占用和实时性均待验证。

此前的网络仅存在于方案中，未形成生产 RTL 或部署模型。本次撤销的是结构、计算量、资源预留及实施计划；不因此声称现有 FPGA 已用资源下降。

## 最终设备脱离上位机运行

用户明确要求：开发阶段可以使用电脑，最终设备必须脱离上位机独立运行。

- 开发阶段：在电脑上用 OpenCV 验证算法、训练线性 SVM、导出定点参数，并完成 RTL 仿真、综合和烧录。
- 运行阶段：摄像头图像处理、候选提取、特征计算、SVM 分类、时序跟踪、超声波测距和提示决策全部由 FPGA 完成，不向电脑发送图像请求识别，也不等待电脑下发判断结果。
- SVM 权重、偏置及固定阈值规划为板上 ROM/存储初始化内容；语音录音由外置语音模块及其 TF 卡保存，运行时无需电脑提供模型或音频。
- FPGA 通过串口控制语音模块，通过驱动电路控制振动；HDMI 保留用于赛题展示与调试，识别和提示不依赖电脑显示程序。
- 按板卡配套流程将配置固化到启动存储，使用适配的独立电源。验收时断开电脑及 USB 调试线，断电重启，检查自动配置、摄像头初始化、识别、测距和语音/振动均能恢复。

以上为目标架构及验收要求，尚未表示新增识别功能和整机脱机启动已经完成实测。

## 外设如何占用资源

- 超声波模块在板外，FPGA 实现触发/回波计数或 UART、超时和结果过滤。
- 语音、TF 卡和音频解码留在 DFPlayer 等外置模块；FPGA 发送命令，不在片上保存整段语音。
- 振动电机由外部驱动供电，FPGA 提供控制或 PWM。
- 以一个双线测距接口、一个双线语音串口、两个振动控制和两个外置按键计算，先预留 8 个 GPIO；语音 BUSY 可再增加 1 个。IMU 另行预留接口。
- GPIO 是否可用必须结合实际排针、已有引脚占用和板载复用电路确定。扩展接口逻辑电平按手册为 3.3V，外设供电能力要独立核算。
- 外设固定在扩展板或外壳上，不要求放在 FPGA 开发板 PCB 表面。没有外壳尺寸和安装位置前，不能保证整体穿戴体积。

## 信号灯：多特征与线性 SVM

建议流水：颜色与局部亮度/边缘候选 → 受限连通区域 → 裁剪与尺寸归一化 → 颜色、方向和形状特征 → 线性 SVM → 目标关联与灯态确认。

- 首版优先面向行人信号灯，标注时区分目标灯态与非目标干扰。车行灯是否纳入需另定测试范围。
- 特征候选为颜色比例、轮廓方向统计和区域形状。先在电脑上比较组合，选择实拍效果达标且适合定点实现的版本。
- 线性分类得分按 `score = sum(weight[i] * feature[i]) + bias` 计算，采用共享乘加单元、固定权重存储和小图缓存；特征提取、归一化和裁剪的开销也必须计入。
- 如采用简化方向直方图或近似归一化，训练、验证与 FPGA 必须使用同一特征定义，不能直接沿用另一种 HOG 实现的权重。
- 分类得分不足、类别得分接近、裁剪不完整或结果超时时输出“未确认”。未经校准的 SVM 得分不当作概率。
- 用位置、尺寸和外观关联连续帧，只对同一目标确认灯态；丢失、过期和矛盾结果清除旧提示。连续帧确认不能消除稳定的误识别。

裁剪尺寸、特征维数、权重位宽和并行乘加数量均在样本验证与独立模块综合后确定，不沿用已撤销的网络计算量或推理延迟估算。

## 地面识别分支

| 目标 | 方案方向 | 输出 |
|---|---|---|
| 盲道 | 颜色候选、条纹方向、受限连通区域和中心线连续性 | 偏离、转弯、分岔、丢失 |
| 提示盲道 | 候选区域中的圆点排列与纹理分析，必要时评估线性 SVM | 前方提示区域 |
| 斑马线 | 成组边缘、明暗交替和透视关系验证 | 候选位置、走向 |
| 普通人行道 | 在指定场景验证铺装、路缘和区域连续性 | 候选区域；不据此给出通行保证 |

盲道偏离与前方转弯分开判断；分岔报告候选方向，暂不替使用者选择路线。未识别到路径时清除旧方向，不继续沿用上一次识别结果。

## 获取候选区域与帧关系

建议从 AWB 后 RGB 分出颜色和局部亮度/边缘候选支路，合并后结合尺寸、形状和受限连通区域统计，输出最多 4 个候选框。灯态分类器既要接收正样本，也要接收衣服、招牌、车尾灯等易混淆负样本。

候选定位若在一帧结束才完成，就无法凭空回读此前未保存的像素。首版建议使用上一帧候选框，在下一帧的原始分辨率 RGB 流中截取、保持比例并缩放到选定的小图尺寸；初次获取会增加至少一次跨帧等待。为框和裁剪图保存帧号/时间，运动过快、裁剪越界或超时均丢弃。

为控制缓存，先安排每帧截取一个候选，最多 4 个候选轮询，使用小图双缓冲；忙时跳过旧任务，不反压视频流。目标总处理量按最多 40 个候选区域/秒评估；如果持续有 4 个候选，约对应每个候选 10 次/秒。视频链路仍保留既有 720p60 配置，识别结果更新频率单独统计。

候选阶段一旦漏掉真实灯，后级分类器无法补救。验收必须同时统计候选召回率、分类混淆和最终端到端结果，不能只报告预先裁剪好图片上的分类准确率。

## 联合资源规划

撤销之前为小网络预留的逻辑、存储和 DSP 预算，以及由此算出的整机占用。替换为 SVM 后仍需实现特征提取、归一化和小图缓存，不能简单从旧预算减去网络一行就得到新的总量。

| 新增部分 | 资源评估重点 | 状态 |
|---|---|---|
| 多特征提取与线性 SVM | 梯度/直方图、归一化、共享乘加、权重和特征缓存 | 待特征确定和独立综合 |
| 盲道、灯候选与斑马线分析 | 行缓存、受限标签表、候选框、裁剪缩放 | 待原型验证和独立综合 |
| 外设控制、决策与结果交接 | UART、测距计数、PWM、事件调度和跨时钟接口 | 待实现和综合 |
| 整机 | 综合后资源合计、布局布线、时序和实测延迟 | 待集成验证 |

继续争取将逻辑占用控制在约 85% 或以下，作为工程留量目标而非器件硬性门槛。数量未超限也不能代替最终布局布线和时序检查。

盲道和灯候选应限制处理区域、标签数量和候选数量。标签表溢出需报告无效，不能静默给出方向；首版不规划无限标签、720p 四像素并行的通用连通区域标记器。

既有构建中可研究的优化方向（以下数字属于前述历史基线，均需单独验证；本次不实施优化）：

1. 简化延迟显示的图表、字符和格式化逻辑，保留有用的延迟读数。历史构建比较显示整项延迟可视化增加 1,448 个 Slice，不能假设全部都可释放。
2. 运动检测设为可选编译功能。基线中的 `u_motion` 占 10 个 ERAM，稳定器另占逻辑；如穿戴版不用该演示功能，可在综合时移除。运行时按键切换不会释放硬件。
3. 简化 Logo 的存储表示，保留赛题要求的安路标识。基线中的 Logo ROM 占 10 个 ERAM，实际可节省多少以新版本综合为准。
4. 保留图像采集、必要 ISP、稳定显示和跨时钟正确性，不以降低画质或破坏帧关系换取纸面资源。

## 实施验证顺序

1. 用实际摄像头采集候选灯与负样本，确定安装视角、最小目标尺寸和灯类别；按场景/录制批次划分训练与验证，避免相邻帧泄漏。
2. 比较纯规则/模板与多特征线性 SVM，训练分类器并验证误报、漏检、灯态混淆和未确认输出；同时验证盲道与斑马线规则。
3. 确定定点特征、权重和分类阈值，建立整数参考模型；对照固定测试向量验证特征值、舍入、饱和和分类结果。
4. 实现特征提取、分类器和共享乘加 RTL，在安路 TD 中独立综合，测得真实 Slice/ERAM/DSP、周期数和时序后更新预算。
5. 加入裁剪和候选流水，验证帧号、初次获取、目标移动、多个候选、标签溢出和结果过期。
6. 与盲道、超声波、语音和振动联调，跑完整布局布线并测量端到端延迟。

倒计时 OCR、通用行人检测、地面落差识别暂列后续扩展，需单独验证算法和资源，不能视为灯态分类器已经具备的功能。
