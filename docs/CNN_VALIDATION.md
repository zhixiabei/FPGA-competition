# CNN 修正与验证

当前活动模块为 `user_source/hdl_source/cnn/cnn_infer_32.v`，
由 `isp_top` 从 AWB 输出取数。FPGA 综合、布局布线和烧录由用户执行。
本文所述修改不会自动更新已有 bit。

## 2026-10-18 修正

- ERAM 是同步读。`NOREG` 只关闭额外输出寄存器，
  `CLKMODE="ASYNC"` 不代表组合读。Conv1/Conv2 的读请求、
  权重、补零标志和首尾标志现在一起延迟；Conv2 保留乘积流水。
- 默认 `C1_SHIFT=8`、`C2_SHIFT=9`。权重仍有 7 位小数，
  导出偏置仍有 14 位小数。Conv1 输出 Q6，
  Conv2 累加器 Q13，所以加入 `B2 >>> 1`；Conv2 输出 Q4。
- 池化直接保留 1024 个激活的原始和，不先截成 8 位平均值。
  17 位无符号池化和表示 Q14 的平均特征；与 Q7 权重相乘后为 Q21，
  因此分类层加入 `BF <<< 7`。原始和上限为 130048，
  当前权重的分类累加绝对上界小于 2^28，32 位有符号累加器足够。
- 保留 ReLU 后 0..127 限幅；并非保证所有可能输入都不饱和。
- 已完成帧只在未被推理占用的 bank 中采集。过快来帧整帧丢弃，
  并置 `O_overrun`，防止混入下一帧像素。
- 帧首可独立于有效像素提前到达。提前帧首会复位坐标和帧状态；
  行长错误或短帧不会作为完整输入发布。
- HDMI 用绿色两像素边框标出实际中心裁剪范围：
  x=512..767、y=232..487。CNN 仅在此 256×256 区域每隔 8 像素抽样，
  输入仍为 `(R+2G+B)>>3` 的 32×32 灰度图。
- 类别编号保持 `OK=0, NOTHING=1, PEACE=2, PUNCH=3, STOP=4`。
  复位、非法类别或连续 60 个显示帧没有新结果时显示 `NOTHING`。
  超时只清除过期结果，不判断画面是否存在手。

W1/W2/WF 有效权重分别为 72/1152/80 字节。
原始导出在 `D:\vivado_work\fpga_artifacts\fpga_artifacts\fpga_weights`。
此前 W2 在低地址 162 插入了一个 `ee`，造成之后的地址整体错位，
最后一个原始字节 `19` 丢失；共 972/1152 个有效权重不一致。
只删除最高字节不能修复该问题。本次已按原始导出恢复完整顺序，
W1/W2/WF/B1/B2/BF 共 1333 个参数逐值一致。
参考脚本同时检查字面量长度和原始导出参数的固定 SHA256，
避免再用损坏的 RTL 权重生成同样损坏的参考结果。

## 本地验证

在工程根目录执行：

```powershell
.\sim\run_cnn_fixed_reference.ps1
.\sim\run_cnn_display_status.ps1
.\sim\run_cnn_infer_32.ps1
```

仅核对导出参数（不运行训练或 FPGA 编译）：

```powershell
python .\sim\cnn_fixed_reference.py --check-weights-only --verify-exports D:\vivado_work\fpga_artifacts\fpga_artifacts\fpga_weights
```

第一项使用 ModelSim 与安路厂商 `PH1P_LOGIC_ERAM`、`PH1P_PHY_GSR`
模型，逐项比较独立 Python 空间卷积参考输出的输入、Conv1、Conv2、
池化和、五个分类分数及最终类别；同时覆盖忙时来帧、提前帧首和短帧恢复。
输入包括两套非均匀合成图案；任一被使用的数据出现未知值即失败。

第二项验证中心框、五类字形、显示同步、60 帧超时、同拍新结果优先和
关闭 CNN 叠加的行为。

第三项比较活动模块与备用窄位宽地址实现的逐拍一致性，
使用同步读行为模型。此项不能替代第一项；
原先的组合读替代模型已移除。

本次正确 W2 的厂商模型回归通过 53330 项检查，逐层张量零差异；
日志在 `tmp/cnn_fixed_reference_20261018_173249/simulation.log`。
两种地址实现的等价回归通过 4165158 项比较、有效消费路径无未知值，
覆盖提前 SOF、丢帧与错误行。HDMI 独立回归通过 1085440 个像素、
2032 个裁剪框边框像素、五类标签和超时；既有图效、单框、多框回归也通过。
这些测试未生成 bit，也不构成修改后资源占用或布局布线时序报告。

## 识别准确率的边界

这些验证证明 RTL 符合当前导出参数的整数计算，不证明真实手势准确率。
已只读核对工程目录外的原始 `model.pt`、类别清单和数据集摘要：
模型记录为 `tiny`、32×32 单通道，五类编号与 RTL 相同；
数据集摘要为 4015 张、每类 803 张。checkpoint 记录的验证准确率为
56.2733%，这是原模型保存的指标，并非本次重新实测。
原始导出符合 `round(weight*128)` 后夹到 -128..127、`round(bias*16384)`；
其中 Conv2 两个、分类层五个权重发生裁剪。

按用户要求，模型本身的低准确率、权重量化裁剪、训练与输入预处理问题
留在模型工程单独处理。本次没有修改 checkpoint、原始 `.mem`、训练数据或模型结构。
checkpoint 未保存 resize、灰度系数、归一化或 ROI 规则；
目前也未取得训练脚本和真实标注图片，不能声称摄像头输入已与训练完全一致。
后续模型工作应使用真实摄像头样本分别统计各类召回率和无手势误报，
提供经过验证的模型、预处理规范和导出参数后，再更新 FPGA 接口。

此前“99.2% 一致率”不能作为准确率改善的证据：
此前 120 张合成输入中，旧计算全部判为 STOP，而连续数值参考有 119 张 STOP；
119/120 只是这种类别分布下的一致率。旧等价仿真也未验证厂商 RAM 的真实读时序。
不再用该指标选择移位参数或声称识别可靠。

当前没有凭空设置分类置信度阈值、肤色门控或运动门控。
这些功能需要真实正负样本验证；跨帧滤波只能缓解闪烁，
不能代替正确的卷积、量化和训练输入匹配。
